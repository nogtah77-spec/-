# العمودي للتسويق العقاري

منصة عربية متكاملة للتسويق العقاري، صُممت لتقديم تجربة واضحة وسريعة للباحثين عن العقارات، مع صفحات مستقلة للمدن والمناطق، أدوات بحث وتصفية متقدمة، وبنية إدارة داخلية لتشغيل العقارات والعملاء والطلبات والعقود والمحتوى من مكان واحد.

> **اسم المنصة:** العمودي للتسويق العقاري  
> **الاسم الإنجليزي:** Luxury Estate Hub  
> **حالة المشروع:** قيد التطوير والتحسين المستمر

## عن المشروع

يهدف المشروع إلى بناء تجربة عقارية رقمية احترافية تجمع بين:

- عرض العقارات بطريقة منظمة وجذابة.
- مساعدة المستخدم على الوصول إلى العقار المناسب بسرعة.
- تخصيص تجربة التصفح حسب المدينة أو المنطقة.
- توفير معلومات العقار الأساسية بوضوح على الهاتف والديسكتوب.
- استقبال الاستفسارات وطلبات التواصل.
- تمكين فريق الإدارة من التحكم في العقارات والمناطق والمحتوى.
- إدارة رحلة العميل العقارية من الطلب الأول إلى المتابعة والمعاينة والعقد.
- إدارة عقود البيع والإيجار والإيجار المفروش والتقسيط مع الدفعات والمرفقات.
- بناء أساس قابل للتوسع لإضافة الإشعارات وتحسين الظهور في محركات البحث.

المنصة مبنية مع مراعاة طبيعة المحتوى العربي واتجاه الكتابة من اليمين إلى اليسار، مع الحفاظ على هوية بصرية هادئة وفاخرة تعتمد على Midnight Blue والألوان النحاسية الدافئة وخلفيات Warm Ivory.

- الإعلانات والبنرات الذكية.
- مساعد وميزات متابعة للزوار والعملاء حسب الوحدات المفعلة.

## البنية التقنية

المشروع عبارة عن مساحة عمل متعددة الحزم تعتمد على:

- React
- Vite
- TypeScript
- Tailwind CSS
- Express
- PostgreSQL
- Drizzle ORM
- Zod
- Orval
- pnpm Workspaces
- Supabase كبيئة قاعدة البيانات المتصلة بالمشروع.
- Object Storage لمرفقات العقود الخاصة.

### أهم المجلدات

```text
artifacts/alamoudi/       واجهة المنصة ولوحة الإدارة
artifacts/api-server/     خادم الواجهة البرمجية
lib/db/                   مخططات قاعدة البيانات
lib/api-spec/             مواصفات الواجهة البرمجية
lib/api-zod/              مخططات التحقق
lib/api-client-react/     عميل الواجهة البرمجية للواجهة
scripts/                  سكربتات مساعدة للمشروع
.agents/memory/           الذاكرة النشطة والقرارات الدائمة
```

## التشغيل المحلي

### المتطلبات

- Node.js
- pnpm
- PostgreSQL
- متغيرات البيئة المطلوبة حسب إعداد الخادم

### تشغيل الواجهة

```bash
pnpm --filter @workspace/alamoudi run dev
```

### تشغيل خادم الواجهة البرمجية

```bash
pnpm --filter @workspace/api-server run dev
```

### الفحص والبناء

```bash
# فحص TypeScript للواجهة
pnpm --filter @workspace/alamoudi run typecheck

# بناء الواجهة
pnpm --filter @workspace/alamoudi run build

# فحص TypeScript لجميع الحزم
pnpm run typecheck

# بناء المشروع
pnpm run build
```

### قاعدة البيانات

يستخدم المشروع PostgreSQL عبر Drizzle ORM. بناء خادم الواجهة البرمجية لا يغيّر قاعدة البيانات؛ دفع تغييرات المخطط إلى بيئة التطوير يتم بشكل مستقل من خلال:

```bash
pnpm --filter @workspace/db run push
```

لا تُنفذ تغييرات قاعدة البيانات في بيئة الإنتاج دون مراجعة مستقلة وخطة ترحيل واضحة.

## قواعد مهمة للتطوير

- واجهة المنصة النشطة موجودة في `artifacts/alamoudi`.
- خادم الواجهة البرمجية النشط موجود في `artifacts/api-server`.
- مخططات قاعدة البيانات موجودة في `lib/db`.
- استخدم المكونات والعقود الموجودة قبل إنشاء بدائل جديدة.
- حافظ على دعم العربية واتجاه الكتابة من اليمين إلى اليسار.
- حافظ على تجربة الهاتف كأولوية أساسية.
- صفحات المدن تستخدم نظام الفلاتر المشترك مع الصفحة الرئيسية.
- المدينة المثبتة داخل صفحة المدينة ليست فلترًا اختاره المستخدم.
- تحسينات بطاقات المدن تمر عبر نمط إبراز مستقل عن بطاقات الصفحة الرئيسية.
- لوحة الألوان الأساسية: Midnight Blue `#10202D`، Warm Brass `#B99A68`، Warm Ivory `#F5F3EE`.
- تستخدم المنصة درجات كحلي ثانوية للبطاقات، وألوانًا مستقلة للنجاح والتحذير والخطأ بدل استخدام الذهبي لكل الحالات.
- لغة البطاقات الموحدة تضع الصورة أولًا، ثم الشارات والكود والموقع والتشطيب والسعر والمواصفات.
- نوع العقار يظهر أعلى يسار البطاقة، وشارة البيع أو الإيجار أعلى يمينها.
- تفاصيل الغرف والحمامات والمساحة تُعرض أفقيًا داخل مستطيلات قصيرة.
- في البطاقات الصغيرة، يبقى السعر قريبًا من التشطيب مع خط فاصل مستقل وتوازن واضح مع الهامش السفلي.
- صور أغلفة المدن تُدار من لوحة الإدارة، مع الإبقاء على خيار الرابط الخارجي.
- صورة غلاف المدينة المرفوعة تُحفظ حاليًا كـData URL داخل حقل الصورة؛ نقل أغلفة المدن إلى التخزين الكائني الدائم مرحلة لاحقة.
- مرفقات العقود، بخلاف أغلفة المدن، تستخدم Object Storage الخاص.
- حسابات الموظفين تُعرض باسم المستخدم ثم الاسم والدور، وتُحفظ العلاقة بمعرّف الحساب.
- الحقول المتناظرة مثل السعر والمساحة والميزانية تُجمع في نطاقات «من» و«إلى».

## تعليمات الوكلاء والذاكرة

لضمان أن يفهم أي Agent المشروع في المستقبل:

- اقرأ `AGENTS.md` قبل بدء أي مهمة.
- اقرأ `replit.md` لمعرفة بنية المشروع وقواعد التشغيل.
- اقرأ `.agents/memory/MEMORY.md` ثم افتح موضوع الذاكرة المرتبط بالمهمة.
- اعتبر `.migration-backup` نسخة احتياطية فقط، وليس مصدر الكود النشط.
- مجلد `.local` يحتوي أدوات وتعليمات Replit المُدارة، ولا يُعدّل عادة ضمن ملفات المشروع.
- خزّن في الذاكرة القرارات الدائمة فقط، ولا تحفظ الأسرار أو البيانات الشخصية أو سجل التغييرات المؤقت.

## النشر

مرجع النشر الرسمي موجود في [`docs/deployment.md`](docs/deployment.md)، وإعداد
Vercel النشط موجود في [`vercel.json`](vercel.json). مجلد الإخراج الصحيح هو:

```text
artifacts/alamoudi/dist/public
```

لا تستخدم مجلد `public`، ولا تنفذ تحديث مخطط قاعدة البيانات أثناء البناء. بعد
اكتمال العمل والاختبارات ورفع Commit إلى `main`، يبدأ النشر التلقائي حسب إعدادات
المستودع.

## التحقق قبل التسليم

بعد تعديل الكود:

1. شغّل فحص TypeScript المناسب.
2. شغّل البناء المناسب.
3. أعد تشغيل سير العمل المتأثر.
4. راجع سجلات الخادم والواجهة.
5. عاين التغييرات المرئية على الهاتف والديسكتوب عند الحاجة.
6. لا تنفذ `git push` إلا بعد مراجعة التغييرات وبطلب واضح من مالك المشروع.

## الحالة والتحقق

الحالة الحالية هي مرحلة تحسين وصقل فوق أساس وظيفي متكامل، مع أولوية تجربة الهاتف والأداء ووضوح البيانات. بعد تغييرات الواجهة أو الخادم يتم التحقق من:

- فحص TypeScript للحزمة المتأثرة أو للمشروع كاملًا.
- بناء الواجهة والمشروع.
- إعادة تشغيل سير العمل المتأثر.
- مراجعة سجلات الواجهة وخادم الواجهة البرمجية.
- معاينة الهاتف وسطح المكتب عند وجود تغيير مرئي.
- فحص تنسيق Git عبر `git diff --check`.

طلبات `401` لمسارات الإدارة عند الزائر غير المسجل متوقعة بسبب حماية المسارات.

## خارطة التطوير

الأولوية الحالية هي الحفاظ على جودة تجربة الهاتف والأداء واستقرار التصفح. وتشمل المراحل التالية عند اعتمادها:

- إشعارات فورية للإدارة عند وصول استفسار أو طلب جديد.
- إدارة متكاملة للعملاء المحتملين من أول استفسار حتى إتمام الصفقة.
- نقل صور أغلفة المدن إلى تخزين كائني دائم لتقليل حجم بيانات قاعدة البيانات.
- تحسين SEO لكل عقار ومنطقة.
- اختبارات آلية ومراقبة إنتاجية أوسع.

## ملاحظات أمنية

- لا تضع كلمات المرور أو مفاتيح الاتصال أو الأسرار داخل ملفات Git.
- استخدم متغيرات البيئة أو نظام الأسرار المعتمد في بيئة التشغيل.
