# Alamoudi seed + import

The `alamoudi` artifact is UI-only (React + localStorage, no backend, user's explicit choice).

## Seed baking + migration
- Property data is baked into `src/data/seedProperties.ts` (generated by `scripts/genSeed.ts` from the user's Excel via `gen:seed`). All visitors see it.
- `DataContext` seeds new users on first load; for existing users it merges only seed properties whose `code` is missing, and writes `alamoudi_seed_version` to localStorage so it does not re-seed.
- **Why:** lets admins edit/delete baked listings without them reappearing on reload.
- **How to apply:** bumping `SEED_VERSION` re-runs the missing-by-code merge — this can resurrect listings an admin deleted, because deletions are not tracked in a ledger. Only bump the version when that trade-off is acceptable, or add a deleted-codes ledger first.

## Import (daily refresh)
- `importProperties` upserts by exact `code`. Rows with a matching code update in place; rows without a code get a generated `ALM-#####` code, so re-importing the same row without a code creates duplicates.
- **How to apply:** the daily-refresh workflow only stays duplicate-free if source rows carry stable codes. The user's Excel does (genSeed preserves codes, suffixes dup codes with `-2`).
- Parser lives in `src/lib/propertyImport.ts` (Arabic digit conversion, مليون/ألف price parsing, sheet-name→region/category, source→agentType). Accepts xlsx/xls/csv/txt/tsv.

## `source` privacy limitation (inherent)
- `source` is hidden from the public UI (never rendered in `PropertyDetails`) but is still present in the shipped bundle (seed file) and in localStorage.
- **Why:** with no backend, any baked/admin field is technically extractable client-side. True privacy would require a backend + auth. UI-hiding is the max achievable under the user's chosen architecture.
